# procurement-agent — агент закупок на Claude Agent SDK

Готовит черновик заявки поставщику: сам считает потребность, сверяет позиции, записывает
черновик — только после «да» человека.

```bash
uv sync
uv run python -m agent.procurement_agent claude-haiku-4-5   # нужен установленный Claude Code
uv run pytest                                              # 10 тестов, модель не вызывается
```

## Устройство

- **Инструменты — свой MCP-сервер в процессе** (`create_sdk_mcp_server`): `get_reorder_plan`,
  `get_part`, `draft_purchase_request`. Расчёт не дублируется — это `ops.procurement.plan`, та же
  функция, что у раздела «Закупки» и фоновой задачи ops.
- **Встроенных инструментов Claude Code нет** (`tools=[]`): ни файлов, ни терминала, ни веба.
  Настройки и правила пользователя не подхватываются (`setting_sources=[]`).
- **Два предохранителя в коде, а не в промпте:**
  - `PreToolUse`-хук отклоняет заявку, где позиции нет в расчёте или количество больше
    рекомендованного в 1.5 раза; модель получает причину и правит заявку сама;
  - `can_use_tool` спрашивает человека перед записью. `allowed_tools` пуст сознательно:
    разрешённый там инструмент проходит мимо `can_use_tool` (SDK об этом предупреждает),
    а решение по каждому вызову должно приниматься в одном месте.
- **Лимиты хода:** `max_turns=10`, `max_budget_usd=0.5`.

## Живой прогон (Haiku 4.5)

```
get_reorder_plan → get_part ×11 → draft_purchase_request
СПРОСИЛ ЧЕЛОВЕКА: Записать черновик заявки: HU-AURIO-S1-9×5, FR-OMODA-C5-9×4, …  → да
Заявка: 16 позиций, 38 единиц, 548 140 ₽. Исключено 90 позиций «Не продаётся».
num_turns=19, total_cost_usd=$0.042
```

Цифры сошлись с разделом «Закупки» дашборда (16 позиций на 548 140 ₽).

Что нашёл первый прогон: модель сочла параметры расчёта обязательными и вместо работы задала
вопрос — в схеме инструмента они стали необязательными со значениями по умолчанию.

Что можно сократить: агент проверяет `get_part` каждую позицию, хотя расчёт уже несёт цену
и остаток. Достаточно сузить инструкцию — ход станет заметно короче.
