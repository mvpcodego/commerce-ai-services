# knowledge-rag — поиск и ответы по базе знаний магазина

RAG над базой знаний того же магазина автомагнитол: карточки автомобилей (какая рамка, проводка,
какие готовые комплекты), карточки магнитол, наборы аксессуаров и статьи FAQ. Вопрос покупателя →
гибридный поиск в PostgreSQL → ответ только по найденным фрагментам со ссылками `[doc_id]` и
проверкой, что каждая ссылка ведёт на фрагмент, который реально был в контексте.

**Данные синтетические.** Карточки собираются из `seed/demo-data.json` (вымышленный каталог),
14 статей FAQ (`rag/faq.py`) написаны для демонстрации: сроки доставки, гарантия, цены установки
выдуманы и не описывают ни один реальный магазин.

## Запуск

```bash
uv sync
docker compose up -d                 # pgvector/pgvector:pg16 на 127.0.0.1:5435
uv run python -m rag.load            # корпус → чанки → эмбеддинги → Postgres (модель ~0.5 ГБ качается при первом запуске)
uv run python -m rag.eval            # метрики поиска; --rerank добавляет кросс-энкодер (~0.6 ГБ)
uv run pytest                        # 29 тестов; 6 из них с БД, без Postgres пропускаются
uv run uvicorn rag.api:app --port 8095
```

```bash
curl -s localhost:8095/ask -H 'content-type: application/json' \
  -d '{"question": "Какая рамка нужна и есть ли CAN-шина?", "make": "Haval", "model": "Jolion"}'
```

`uv run python -m rag.corpus` пишет корпус в `data/corpus.jsonl`, чтобы его можно было прочитать глазами.

## Как устроено

- **Корпус** (`rag/corpus.py`): 98 документов — 40 автомобилей, 34 магнитолы, 10 наборов, 14 FAQ.
  Генерация детерминированная. У документа есть тип, марка и модель (у карточек машин).
- **Чанкинг** (`rag/chunking.py`): по предложениям до 500 символов, перекрытие в одно предложение.
  Заголовок документа добавляется к чанку при индексации. Получается 235 чанков.
- **Хранилище** (`migrations/001_init.sql`): `vector(384)` с индексом HNSW (cosine) и `tsvector`
  (конфигурация `russian`, заголовок с весом A, текст с весом B) с индексом GIN. Метаданные продублированы
  в чанках, фильтр по марке и модели не требует join. `hnsw.iterative_scan` добирает строки, когда фильтр
  отсекает часть найденного индексом.
- **Эмбеддинги** (`rag/embed.py`): `intfloat/multilingual-e5-small` через fastembed (ONNX, CPU, без ключей),
  с префиксами `query:` / `passage:`. В списке fastembed этой модели нет, она регистрируется как
  пользовательская из ONNX-файла её репозитория. Какой моделью построен индекс, записано в `kb_meta`,
  и API кодирует вопрос той же моделью.
- **Поиск** (`rag/retrieval.py`): вектор и полнотекст по 30 кандидатов, слияние Reciprocal Rank Fusion
  (k = 60). Полнотекст строится парсером Postgres из вопроса, слова соединяются через OR. Фильтр по марке
  и модели пропускает и общие документы (FAQ, магнитолы), а выбранная машина дописывается в текст запроса.
  Режим `rerank` переранжирует верхние 20 гибридных фрагментов кросс-энкодером
  `BAAI/bge-reranker-v2-m3-int8` (fastembed); в API включается `RAG_RERANK=1`.
- **Ответ** (`rag/answer.py`): контекст набирается фрагментами по рангу в бюджет токенов (оценка
  ~3 символа на токен, фрагмент целиком или никак). Модель за интерфейсом `LLM`. По умолчанию
  `ExtractiveLLM`: без генерации, берёт предложения контекста с наибольшим совпадением слов
  и ставит к каждому ссылку. `RAG_LLM=openai` (любой OpenAI-совместимый сервер: `RAG_LLM_BASE_URL`,
  `RAG_LLM_API_KEY`, `RAG_LLM_MODEL`) или `RAG_LLM=anthropic` (`ANTHROPIC_API_KEY`, `RAG_LLM_MODEL`)
  включают настоящую модель. Ссылки на документы, которых нет в контексте, помечаются прямо в тексте
  (`[faq-warranty — нет в источниках]`) и возвращаются в `unknown_citations`, `grounded` становится `false`.

## Качество поиска

36 размеченных вопросов (`eval/questions.jsonl`): 17 перефразированных вопросов к FAQ, 9 по автомобилям,
6 по магнитолам, 4 по наборам. Метрики по документам (чанки одного документа схлопываются в лучшее
место). Recall@5 нормирован на min(|релевантных|, 5).

Прогон 19.10.2026, e5-small, 98 документов / 235 чанков:

| Режим | Recall@5 | MRR | nDCG@5 | Вопросов без единого попадания в топ-5 |
|---|---|---|---|---|
| vector | 0.956 | 0.981 | 0.947 | 0 |
| fulltext | 0.789 | 0.796 | 0.783 | 7 |
| hybrid (RRF) | 0.928 | 0.890 | 0.887 | 2 |
| hybrid + rerank | **0.969** | **0.986** | **0.968** | 0 |

Для сравнения тот же набор с запасным `HashEmbedder` (символьные триграммы вместо модели):
vector 0.831 / 0.791 / 0.779, hybrid 0.817 / 0.802 / 0.785.

Задержка на M-серии Mac, CPU, после прогрева: vector p50 10 мс, fulltext 2 мс, hybrid 11 мс,
hybrid + rerank 2,8 с (кросс-энкодер на 20 парах).

Что видно из таблицы:

- **Гибрид здесь хуже чистого вектора.** Вопросы набора в основном перефразированы («Сколько ждать
  посылку в Екатеринбург?» вместо «доставка»), полнотекст на них промахивается в 7 случаях из 36 и через
  RRF тянет вниз правильные ответы вектора. На двух вопросах про установку («поставить магнитолу у вас»,
  «сам поставить комплект») полнотекст уверенно поднимает карточки машин, где много раз встречаются
  «магнитола» и «комплект», и гибрид теряет FAQ из топ-5. Веса RRF под этот набор я не подбирал:
  набор маленький, и подгонка под него ничего не доказала бы.
- **Кросс-энкодер исправляет это**, но стоит почти 3 секунды на вопрос на CPU.
- **Вес заголовка в tsvector** (A против B) поднял полнотекст с 0.761 / 0.758 / 0.747 до
  0.789 / 0.796 / 0.783, гибрид от этого не изменился.

## Ограничения

- Набор вопросов размечал тот же, кто писал корпус, и вопросы написаны под этот корпус. Цифры показывают,
  что конвейер работает и как соотносятся режимы, но не качество на настоящих вопросах покупателей.
- Корпус маленький (98 документов): HNSW здесь не нужен по скорости, он стоит ради схемы, которая
  выдержит рост. Карточки магнитол одной серии почти одинаковы (отличаются диагональю и ценой),
  поиск их путает между собой.
- Поиск по точному артикулу магнитолы (`HU-VERTEK-V3-101`) полнотекстом находит карточки машин,
  где этот артикул стоит в списке комплектов, а не карточку магнитолы. Для артикулов нужен отдельный
  точный поиск по ключу, его нет.
- Качество ответов не измерялось, только поиска. `ExtractiveLLM` не понимает смысл вопроса:
  на «Сколько стоит доставка на Марс?» он отвечает «нет ответа» только потому, что совпало меньше двух слов.
  `grounded` проверяет, что ссылки ведут на найденные фрагменты, но не проверяет, что фрагмент
  действительно подтверждает утверждение.
- Вызов OpenAI-совместимой модели и Anthropic написан, но в этой работе не запускался: ключей нет,
  тесты используют фейковую модель.
- Корпус перезаливается целиком, инкрементального обновления нет. Аутентификации у API нет, сервис рассчитан
  на внутреннюю сеть рядом с витриной.
